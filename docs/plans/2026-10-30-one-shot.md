# One-command production plan

**Goal:** Turn athlete, music style and duration into a verified, resumable local MP4, or an explicit evidence-backed blockage.
**Approach:** Reuse the catalogue, permission records, music analysis, action planner and FFmpeg renderers. Integrate the Crawford production lessons at their shared boundaries; keep automated candidates distinct from established action boundaries and licence evidence.
**Stack:** Existing Python package, FFmpeg/FFprobe, NumPy/OpenCV, yt-dlp, pytest, GitHub Actions, local disk-guard.
**Spec:** User mission of 2026-10-30, following Crawford V2 delivery.

## 1. Audit and preserve baseline
- Files: all tracked source/tests/configuration, production scripts and Crawford V2 reports (read only); `docs/ONE_SHOT_AUDIT.md`.
- Intent: map working interfaces, missing automation, dependencies, remote differences and storage limits. Preserve the dirty journal, existing plans, banner and media.
- Check: baseline pytest; doctor; remote HEAD and local history; hash Crawford reference and banner. Record concrete failures rather than claiming universal autonomy.
- Risks: current free disk is below the normal 12 GB floor; do not carry the earlier production exception into this mission.

## 2. Quality and bounded audio recovery
- Files: `src/youtube_edit_ultra/render.py`, new `quality.py`, `produce.py` compatibility export, relevant tests.
- Intent: prevent limiter auto gain and encoded true-peak overshoot; persist failed QC; automatically repair audio with bounded retries, preserve H.264 packets, verify again. Tight duration/frame expectations and explicit review scope.
- Interface: verification callable remains compatible with `produce.verify_output`; repair returns verified artifact and evidence, never silently replaces a personal/source file.
- Check: true-peak regression, real FFmpeg decode/repair and identical video packet hashes; existing ambience/timing tests.
- Risks: repair needs storage; keep failed state resumable and never ignore disk refusal.

## 3. Editorial and sourcing readiness
- Files: `spec.py`, `catalogue.py`, `music_sources.py`, `editorial.py`, `vision.py`, `semantic.py` as required by audit; component tests.
- Intent: parse the three requested examples and unknown athlete names; distinguish personal and commercial permission scope; reuse local/authorized acquisitions; portable music structure analysis; deduplicate and protect complete documented action cores. Recognizer uncertainty must block delivery rather than fabricate validated actions.
- Check: request/style/era tests; licence-mode tests; insufficient-resource and duplicate cases; complete combination/KO boundaries and exact duration tests.
- Risks: a motion peak is not a verified boxing action; a licence string is not independently verified ownership.

## 4. One-shot orchestration and recovery
- Files: new job orchestration module, `cli.py`, `produce.py`, `pyproject.toml`, storage helper if needed; job/integration tests.
- Intent: `ueu create "athlete — style — duration"` calls independent cached stages, writes an atomic manifest, resumes by job id/path, preserves proven artifacts, reports precise failures, reserves disk before heavy stages, cleans only validated job-owned temporary files.
- Interface: retain `ultra create`, `ultra produce`, catalogue and Spotify APIs; unique output directory, JSON manifest and readable report; no implicit publication.
- Check: one-prompt licensed fixture video; interrupted-stage resume; corrupt cache; storage refusal; safe cleanup; final delivery integrity.
- Risks: cached results must bind to inputs/settings; concurrent jobs must not reuse mutable outputs or consume the same reserved space.

## 5. Demonstration, review and GitHub
- Files: README, installation/config examples, CI, audit/results documentation, project journal.
- Intent: demonstrate the installed command with a short authorized fixture and available real material within storage limits; report executed versus simulated versus blocked tests. Review all changes and publish coherent commits to configured GitHub remote.
- Check: full suite, lint/build as applicable, clean diff, secret/large-file scan, independent whole-change review, remote commit SHA and CI results.
- Risks: never publish local personal media, credentials, machine-specific paths or private-use rights as reusable licences. No banner changes. No deletion of supposedly obsolete scripts without caller evidence.

Human checkpoints are already authorized by the mission: normal reversible edits, tests, commits and push. New account grants, unavailable rights, destructive personal-file changes, or disk-floor exceptions remain explicit blockers.
